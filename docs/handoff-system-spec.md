# Blueprint: ระบบส่ง–รับงาน (Handoff Gate) + 1 คนหลายตำแหน่ง

เอกสารนี้คือโมเดลก่อนเขียนโค้ด — ยืนยันก่อนสร้าง เพื่อกันแก้ซ้ำและกัน conflict กับเอเจที่ทำบอร์ด

---

## 1. หลักการ: ทุกรอยต่อ = ด่านส่ง–รับ 2 ฝั่ง

```
[ผู้ส่ง] กด "ส่งงาน"  →  งานเข้าสถานะ "รอตรวจรับ"  →  [ผู้รับ] ตรวจ
                                                        ├─ ถูก → "รับงาน" → เด้งขั้นถัดไป
                                                        └─ ไม่ถูก → "ตีกลับ" + เหตุผล → กลับขั้นเดิม
```

ใช้แพทเทิร์นเดียวกับที่มีอยู่แล้ว (รับงานข้ามสาขา + ยืนยันมัดจำ) — ทำเป็น **เครื่องมือกลางตัวเดียว** reuse ทุกด่าน

---

## 2. ตาราง 4 ด่านหลัก  ⚠️ ช่วยยืนยัน/แก้ตรงนี้

| # | ด่าน | จากสถานะ | ผู้ส่ง | ตรวจที่สถานะ | ผู้ตรวจ/รับ | ผ่าน → | ตีกลับ → |
|---|------|----------|--------|--------------|------------|--------|----------|
| 1 | ออกแบบ → อนุมัติแบบ | กำลังออกแบบ | กราฟิก | รอลูกค้าอนุมัติ | เซล | พร้อมผลิต | กำลังออกแบบ |
| 2 | อนุมัติแบบ → ผลิต | พร้อมผลิต | เซล / ผจก. | (รับเข้าผลิต) | ฝ่ายผลิต | กำลังผลิต | พร้อมผลิต |
| 3 | ผลิต → QC | กำลังผลิต | ฝ่ายผลิต | ตรวจคุณภาพ | QC | แพ็กของ | กำลังผลิต |
| 4 | QC → จัดส่ง | แพ็กของ | ฝ่ายแพ็ก | จัดส่ง / รับแล้ว | ฝ่ายจัดส่ง | จัดส่ง / รับแล้ว | กำลังผลิต |

> หมายเหตุ: ด่านการเงิน (เสนอราคา→มัดจำ→ยืนยัน) ที่เพิ่งทำใน B ก็คือด่านชนิดนี้ — ใช้กลไกเดียวกัน

---

## 3. กฎ 4-eyes (กันคนเดียวส่ง+รับเอง)

- **ผู้รับต้องเป็นคนละคนกับผู้ส่ง** — แม้คนคนเดียวจะมีหลายบทบาทก็รับงานที่ตัวเองส่งไม่ได้
- ข้อยกเว้น: **เจ้าของ override ได้** (มีปุ่ม "ยืนยันแทน" เมื่อจำเป็น และระบบบันทึก audit ว่าใคร override)

---

## 4. เรื่อง 1 คนหลายตำแหน่ง (multi-role)

- พนักงาน 1 คนถือได้ **หลายบทบาท** (เช่น เป็นทั้ง เซล + กราฟิก)
- สิทธิ์ = **รวมสิทธิ์ของทุกบทบาท** (union)
- คุณสมบัติเป็น "ผู้ตรวจ" ของด่าน = มีบทบาทที่ด่านนั้นต้องการ
- ทำงานคู่กับกฎ 4-eyes ด้านบน — สวมหลายหมวกได้ แต่ยังกันพลาดได้

---

## 5. สิ่งที่ต้องแก้ในระบบ

**ฐานข้อมูล (migration)**
- `profiles.extra_roles text[]` — บทบาทเสริมต่อคน
- `jobs` เพิ่ม: `handoff_status` (none/pending/accepted), `handoff_from_user`, `handoff_from_status`, `handoff_gate`, `handoff_note`

**โค้ด (app)**
- รวมสิทธิ์หลายบทบาท (`can()` / currentRolePermissions)
- เครื่องมือกลาง: `submitHandoff` / `acceptHandoff` / `rejectHandoff` + เช็ก 4-eyes
- ตารางตั้งค่าด่าน (gate config) ตามข้อ 2
- UI: ปุ่ม "ส่งงาน / รับงาน / ตีกลับ(พร้อมเหตุผล)" บนการ์ด + หน้ารายละเอียดงาน + ป้าย "รอตรวจรับ"
- หน้า HR/ผู้ใช้: ติ๊กหลายบทบาทต่อคน
- แจ้งเตือนผู้รับเมื่อมีงานรอตรวจ + audit log ทุกการส่ง/รับ/ตีกลับ/override

---

## 6. แผนสร้างเป็นเฟส (verify + push ทีละเฟส)

- **P1 — Multi-role:** extra_roles + รวมสิทธิ์ + ติ๊กหลายบทบาทในหน้า HR
- **P2 — Handoff engine + ด่าน 1** (กราฟิก→เซล) ครบวงจร + กฎ 4-eyes + UI
- **P3 — ด่าน 2–4** (ผลิต/QC/จัดส่ง)
- **P4 — แจ้งเตือน + audit + override เจ้าของ**

ยืนยันตาราง §2 และลำดับเฟส §6 แล้วผมเริ่ม P1 ได้เลย
